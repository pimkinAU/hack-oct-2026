# Разбор ответов по одному файлу на задание

Здесь подробно расписан каждый из пяти вопросов блока А: что спрашивают, какая
в данных ловушка, откуда берётся каждая цифра, запрос дословно (как в
`model/03_answers.sql`) и что получилось на реальных данных.

| файл | задание | ответ |
|---|---|---|
| [01_monthly_revenue.md](01_monthly_revenue.md) | выручка и число заказов по месяцам | 24 строки, 2016-11 с нулём, итого 13 221 498.11 |
| [02_top_sellers.md](02_top_sellers.md) | топ-10 продавцов по выручке | №1 = 226 987.93 |
| [03_avg_check.md](03_avg_check.md) | средний чек заказа | 159.88 (1.14 строки, 1.14 единицы) |
| [04_customers.md](04_customers.md) | покупатели и повторные покупки | 96 096 человек, 3.12% вернувшихся |
| [05_categories.md](05_categories.md) | выручка по категориям с долей | 74 категории, крупнейшая 1 233 131.72 |

## Одно определение на все файлы

Чтобы пять раз не объяснять одно и то же, правила здесь общие:

* **выручка** — сумма `price` (стоимость товаров, без доставки) по заказам,
  которые стали выручкой;
* **стали выручкой** — это `is_revenue = true`, а этот флаг выставлен один раз
  в `core.dim_order_status`: равняется `order_status = 'delivered'`. Изменить
  определение — значит поменять одну строку там, а не пять запросов здесь;
* **уровень** — у нас две разные таблицы: `fact_order` (одна строка = заказ) и
  `fact_order_item` (одна строка = товар одного продавца в заказе). Чек и
  показатели заказа считаем по первой, выручку продавца и категории — по второй;
* **данные не теряем** — везде `left join`, а потери проверяет
  `model/04_checks.sql` (10 проверок, сверяет строки и суммы с `raw`).

## Как получить эти цифры самому

```bash
bash scripts/setup.sh      # база + сырые данные
bash model/build.sh        # модель, витрины, ответы, проверки
```

Дальше любой из ответов — обычным `select`:

```sql
select * from mart.answer_q1 order by month;
select * from mart.answer_q2;
select * from mart.answer_q3;
select * from mart.answer_q4;
select * from mart.answer_q5 order by revenue desc;
```

Тот же результат печатает `model/03_answers.sql` при сборке, а `04_checks.sql`
сверху добавляет проверки целостности.

## Про контрольные числа

В `docs/tasks.md` к каждому вопросу дано контрольное число. Мы считаем ответ
сданным, только если он совпал целиком, до копейки. Не совпало — значит
определение или уровень выбраны неверно, а не «округлилось».

| вопрос | контроль | у нас |
|---|---|---|
| 1 | 24 строки, одна нулевая, сумма 13 221 498.11 | совпало |
| 2 | у первого 226 987.93 | совпало |
| 3 | 159.88 (неверные: 123.75 и 139.97) | совпало, 139.97 воспроизвели |
| 4 | 96 096 и 3.12% (99 441 — неверный ключ) | совпало |
| 5 | 74 категории, крупнейшая 1 233 131.72, сумма 13 221 498.11 | совпало |
