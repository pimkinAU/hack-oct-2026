# 9. Как платили в 2018: по штатам и по способам оплаты

## Что спрашивают

Платежи за 2018 год по штатам покупателей: штат, число платежей, сумма, средний
срок рассрочки. Отдельно — по способам оплаты: способ, число платежей, средний
срок рассрочки.

## Что в данных

`core.fact_payment` — одна строка на платёж (ключ `order_id + payment_sequential`),
с типом оплаты, числом рассрочек и суммой. Год привязываем по дате ЗАКАЗА, а не
по дате платежа: в выгрузке даты платежа нет, есть только `month_start` самого
платежа, вычисленный из того же заказа.

Год задаём диапазоном, а не `year(...) = 2018`, чтобы индекс по дате работал и
чтобы границы были видны глазами:

```sql
where fo.purchased_at >= date '2018-01-01'
  and fo.purchased_at <  date '2019-01-01'
```

Статусы не отсекаем: вопрос про то, как платили, а платили и за отменённые заказы
тоже. Для сравнения: только доставленные заказы дали бы 54 748 платежа на
8 452 975.20 вместо 56 015 на 8 699 763.05.

Про число рассрочек. В `installments` стоит 1 у обычного платежа, 2..24 у
рассрочки, и всего в 2 строках лежит 0 (незаполненные данные). Поэтому среднее по
всем платежам — 2.85, а по платежам с настоящей рассрочкой (больше 1) — 4.75. В
основном ответе лежит первое, как и просили; второе мы показываем отдельной
колонкой, чтобы цифру нельзя было прочитать неверно.

## Как считали

`mart.answer_q9_state` — штат, платежи, сумма, средняя рассрочка:

```sql
select cu.customer_state,
       count(*)                                   as payments,
       round(sum(p.payment_value)::numeric, 2)    as paid,
       round(avg(p.installments)::numeric, 2)     as avg_installments
from core.fact_payment p
join core.fact_order fo on fo.order_id = p.order_id
join core.dim_customer cu on cu.customer_id = fo.customer_id
where fo.purchased_at >= date '2018-01-01'
  and fo.purchased_at <  date '2019-01-01'
group by cu.customer_state
order by paid desc;
```

`mart.answer_q9_type` — то же по способам оплаты, за всю историю (не только 2018,
так в условии), плюс колонки «сколько платежей с рассрочкой» и «средний срок именно
в них».

## Что заметили

- Рассрочку берут там, где меньше денег, а не там, где больше заказов. Средний
  срок по SP — 2.51, по DF — 2.59, по PR — 2.76, а по PB и RN — 3.62, по SE —
  3.54, по PE — 3.46. Богатые штаты платят сразу, бедные разбивают платёж.
- Рассрочка невозможна без карты: у boleto, voucher и debit_card срок равен 1.
  Из 19 784 платежей boleto рассрочка есть ровно в 2. Значит, вся рассрочка в
  бизнесе — это 51 339 платежей кредитной картой из 76 795 (67%).
- Если читать только «среднюю рассрочку 3.51 по кредитным картам», можно
  подумать, что рассрочкой пользуются все. На самом деле 25 456 платежей картой
  обычными (без рассрочки), а 51 339 — с ней, и внутри них срок 4.75 месяца.
- `not_defined`: 3 платежа на 0.00. Их нельзя выбрасывать молча — из-за них сумма
  по штатам и сумма по способам сходятся только если считать все платежи.
- SP даёт 44.0% платежей 2018 года, но только 39.3% суммы: средний платёж в SP
  138.61, а по стране 155.31. В крупнейшем штате берут чаще и мелче — то есть
  структура платежей не повторяет структуру денег, и сравнивать штаты надо либо
  по сумме, либо по числу платежей, но не смешивать.

## Почему не сделали иначе

- Не считали «средний срок рассрочки» только по платежам с `installments > 1` в
  основной колонке: в условии просят средний срок рассрочки по платежам, и
  подмена базы без отдельной колонки сделала бы цифру неверно понятной.
- Не разбирали платежи по месяцам 2018: в разрезе по штатам это удвоило бы число
  строк, а вопрос был про год целиком. Помесячно видно в `mart.v_payment_mix`.
