# Задание 2. Топ-10 продавцов по выручке

## Что спрашивают

Из `docs/tasks.md`:

> **Результат:** продавец, город, штат, число заказов, единиц товара, выручка.
> **Контроль:** у первого продавца в топе выручка 226 987.93.
> **Куда смотреть.** В одном заказе могут быть товары разных продавцов. Если
> считать выручку продавца от таблицы заказов, одна и та же выручка посчитается
> несколько раз.

## В чём ловушка

Заказ — не единица продавца. В `raw.order_items` у заказа свои строки, и у
каждой строки свой `seller_id`: 1 278 заказов в выгрузке относятся сразу к
нескольким продавцам.

Если взять `fact_order` и приписать всему `goods_total` заказа каждого
продавца из него, сумма по продавцам превысит общую выручку маркетплейса:
один и тот же рубль попадёт в отчёт дважды или трижды. Плюс сломается «число
заказов» продавца — оно начнёт считаться как число заказов целиком, а не как
число заказов, где этот продавец участвовал.

Правильный уровень — таблица позиций `fact_order_item`: строка позиции
принадлежит ровно одному продавцу.

Отдельная мелочь: колонки «единицы товара» в выгрузке нет. Одна строка позиции
= одна единица товара, поэтому `units` у нас считается как `count(*)`.

## Откуда берутся цифры

```
raw.order_items (order_id, seller_id, price)  +  raw.sellers (seller_id, city, state)
   ↓  model/01_core.sql
core.fact_order_item   одна строка = позиция; seller_id, price, is_revenue
core.dim_seller        карточка продавца: seller_id, seller_city, seller_state
   ↓  model/02_mart.sql
mart.v_seller_revenue  одна строка = продавец: заказы, единицы, выручка
   ↓  model/03_answers.sql
mart.answer_q2         первые 10 по выручке
```

## Запрос дословно

Витрина (`model/02_mart.sql`):

```sql
create view mart.v_seller_revenue as
select i.seller_id,
       max(s.seller_city)         as seller_city,
       max(s.seller_state)        as seller_state,
       count(distinct i.order_id) as orders,
       count(*)                   as units,
       sum(i.price)               as revenue
from core.fact_order_item i
left join core.dim_seller s on s.seller_id = i.seller_id
where i.is_revenue
group by i.seller_id;
```

Разбор:

* `where i.is_revenue` — берём только позиции доставленных заказов: выручка
  считается по тому же правилу, что и в первом вопросе;
* `left join core.dim_seller` — внутренний join выкинул бы продавца, у которого
  нет карточки в `raw.sellers`, и его деньги пропали бы из отчёта. С `left join`
  продавец остаётся, просто с пустым городом;
* `max(s.seller_city)` — город один на продавца, но раз мы группируем,
  Postgres требует агрегат вокруг негруппируемой колонки. `max` здесь — способ
  достать единственное значение, а не «самый большой город»;
* `count(distinct i.order_id)` против `count(*)` — первая считается в
  «число заказов», вторая в «число единиц». Разница видна в топе: у продавца
  `4a3ca931...` 1 772 заказа и 1 949 единиц, то есть в части заказов он продал
  сразу несколько своих товаров.

Ответ (`model/03_answers.sql`):

```sql
create table mart.answer_q2 as
select s.seller_id,
       s.seller_city,
       s.seller_state,
       s.orders,
       s.units,
       round(s.revenue, 2) as revenue
from mart.v_seller_revenue s
order by s.revenue desc, s.seller_id
limit 10;
```

`seller_id` в `order by` второй колонкой — на случай одинаковой выручки: без
него база могла бы выдавать разный порядок строк между запусками, и десятка
«плыла» бы при перепроверке.

## Почему нельзя было иначе

* **от `fact_order`** — выручка посчиталась бы по несколько раз для
  многопродавцовых заказов, и сумма по продавцам перестала бы равняться общей;
* **inner join к `dim_seller`** — позиции «безымянных» продавцов выпали бы,
  выручка стала бы меньше;
* **все статусы заказов** — в топ попали бы продавцы, которые почти всё отменили;
* **без `seller_id` в сортировке** — nondeterministic tenth place.

## Что ещё видно из этих чисел

* у первого продавца 1 124 заказа и 1 148 единиц — средний чек по позициям у
  него почти «одна позиция на заказ»;
* девять продавцов из десяти — из штата SP, один из BA: топ очень географически
  кучный (про распределение по штатам — отдельный вопрос, в `STRATEGY.md`);
* у продавца `4a3ca931...` заказов больше, чем у лидера (1 772 против 1 124), а
  выручка меньше: у него дешёвые товары, средняя позиция ~101 против ~198 у
  лидера;
* всего продавцов в справочнике 3 095, из них хоть раз продали 2 970; топ-10
  дают 13.27% всей выручки маркетплейса.

## Как перепроверить

```sql
-- первый продавец и контроль
select seller_id, round(revenue, 2) as revenue
from mart.v_seller_revenue
order by revenue desc
limit 1;

-- сумма по всем продавцам равна общей выручке (проверка №8 из 04_checks.sql)
select round(sum(revenue), 2) from mart.v_seller_revenue;
```

Ожидаем `226987.93` и `13221498.11`.
